# Eval catalog — наблюдавшиеся failure modes

Статус: **девять evidence-backed спецификаций**, не исполняемый suite и не отчёт о новых прогонах. Источники R/S — в [реестре](../evidence/source-register.md). Все suggested pass conditions — операционализация наблюдения для будущего replay, а не новые universal rules.

Негативные состояния ниже репрезентативны: там, где нет сохранённого исходного дампа, они являются описанием реконструкции, а не подлинным export. Исходный факт сбоя явно отделён от реконструируемой проверки. Прогоны по этим карточкам не выполнялись; runtime result для каждой — **not run**.

## E-01 — Incorrect slot fallback hiding

- **Scenario:** Button имеет default sideIcon; потребитель заменяет side на текст CSV, затем меняет настройку наличия fallback-иконки. Отдельно проверяет отсутствие side вообще.
- **Representative bad state:** иконка fallback выключена, но Slot сохраняет её пустое место. Исправление через visible всего Slot убирает место; для будущего eval отдельно проверяется риск, что этот контроль ошибочно выдан за видимость одного fallback и подавляет custom content.
- **Почему правдоподобно:** скрыть контейнер проще, и такая операция уменьшает ширину кнопки. Настоящий SLOT и успешная геометрия создают впечатление соответствия Vue.
- **Observable failure:** пустой fallback продолжал занимать место: S-01 фиксирует shown/hidden fallback 26×18. S-02 показывает workaround 92 → 66 px при скрытии всей области. Отдельного наблюдения «custom CSV исчез при переключении fallback» в найденных источниках нет; это проверяемый риск реконструкции, не ещё один зарегистрированный инцидент.
- **Pass condition:** проверить три состояния: custom content без sideIcon, default sideIcon, отсутствие custom content и sideIcon. Видимость default icon не ограничивает custom content; в пустом состоянии нет фантомного места, не требуемого контрактом. Намеренное скрытие всей области, если оно предусмотрено Figma API компонента, названо отдельно и не выдано за Vue sideIcon. После возврата состояния custom content сохранён.
- **Evidence из Haulplane:** R-03, строка 100, называет переделку «скрытие всего Slot вместо содержимого fallback», не сохраняя весь before/after contract; R-04/R-05 задают семантику; S-01/S-02 уточняют историческую геометрию и workaround. R-02 сообщает работающий CSV, но полной независимой матрицы этой проверки не содержит.
- **Core или adapter:** Figma adapter на границе Vue contract; переносимый смысл «fallback не сужает consumer content» — promotion candidate.
- **Ограничение:** успешный промежуточный workaround не считается окончательным исправлением; нужен replay всех трёх веток. Из этой карточки не следует универсальная обязанность иметь ShowSide.

## E-02 — Author/research notes leaking into product copy

- **Scenario:** агент превращает сценарный brief сравнения кандидатов в рабочую композицию.
- **Representative bad state:** вводное объяснение сравнения, пересказ показанной ETA и подпись Synthetic scenario занимают отдельные зоны интерфейса. Примеры из R-07: “Compare the impact. Selecting a vehicle does not publish the route.” и повтор изменения ETA на 18 минут рядом с самим значением.
- **Почему правдоподобно:** пояснения выглядят заботой о ясности, демонстрируют понимание brief и помогают автору рассказать исследование.
- **Observable failure:** экран объясняет собственное устройство, повторяет данные; появившаяся под пояснения колонка влияет на приоритеты композиции. Первая проба из-за этого не принята.
- **Pass condition:** каждый оставленный текст отвечает на конкретный вопрос пользователя в текущем действии. Источник synthetic data и design rationale вынесены за продуктовый frame; дубль ETA убран; пустая зона после удаления пересобрана. Сохраняются единицы, названия действий, данные и конкретные ограничения, например Driving time unavailable. Независимый просмотр фиксирует, что пользователь понимает выбор, preview и дальнейшее действие без подсказки автора.
- **Evidence из Haulplane:** R-02, строки 96–114, первая проба 4:2 и переделка 20:9; R-07 содержит примеры и мотивы удаления. Переделка остаётся черновиком, UX-pass не записан.
- **Core или adapter:** core promotion candidate. Английский язык — политика Haulplane, не часть общего pass condition.
- **Ограничение:** regex или word limit не являются oracle; полезное предупреждение нельзя удалять только потому, что это предложение длиннее подписи.

## E-03 — Product composition in DS file for tool convenience

- **Scenario:** нужно собрать продуктовый сценарий из неопубликованных компонентов библиотеки; межфайловый канал ещё не подтверждён.
- **Representative bad state:** рабочий сценарий создаётся на служебной странице DS-файла и развивается в экран, потому что локальные masters там доступны. Продуктовый файл пустует; временное исключение становится рабочим порядком.
- **Почему правдоподобно:** за один вызов доступны токены и компоненты, публикацию можно отложить; проба выглядит полезной для проверки foundations.
- **Observable failure:** Haulplane обнаружил три продуктовых фрейма в библиотеке. Переименование в Legacy product drafts — paused и перемещение страницы в конец изолировали долг, но не перенесли продукт. Import неопубликованного header вернул Component ... not found.
- **Pass condition:** в поддерживаемом канале продуктовый фрагмент живёт в продуктовом файле и потребляет библиотечные компоненты с сохранённой связью. В библиотеке остаются только относящиеся к компоненту примеры. При недоступном канале фиксируется blocker; библиотечный экран или локальная копия общей библиотеки не объявляются успешным переносом. Зависимости и принадлежность проверены по артефакту, а не имени страницы.
- **Evidence из Haulplane:** R-02, строки 105–123; R-09; S-05 прямо объясняет причину ошибочного исключения. Узлы 4:2, 13:5, 20:9 в DS-файле.
- **Core или adapter:** Figma adapter и точная политика Haulplane. Общий вывод «инструментальная доступность не определяет ownership» — promotion candidate.
- **Ограничение:** не выводить отсюда запрет product shape в Vue-пакете: R-14 прямо разрешает такой код. Ровно два Figma-файла не объявляются universal architecture.

## E-04 — False green при формальной проверке структуры

- **Scenario:** gate проверяет корректность компонентного набора по манифесту.
- **Representative bad state:** Label связан с текстом в Large, но не в Small; алгоритм собирает одну совокупность связей на весь set и считает наличие достаточным. Соседние наблюдавшиеся случаи — неверный style у Small, ошибочная token binding, stroke без variable, несовпадающее значение exception.
- **Почему правдоподобно:** property определён, связь в set присутствует, набор вариантов непустой; числовые счётчики и типы выглядят правильными.
- **Observable failure:** defective fixture возвращал пустые failures. R-08 явно связывает эти случаи с версиями ворот до b8a8ee1 и последующими пропусками coverage.
- **Pass condition:** bad fixture отвергается по конкретному Small/Label, корректный Large не получает ложный отказ; после исправления связи fixture принимается. Неполный/пустой манифест не даёт PASS. Отчёт отдельно помечает «технически проверено» и «UX/DX not run».
- **Evidence из Haulplane:** R-08, историческое описание прошедших контрпримеров и локального испытания на подставленных API objects.
- **Core или adapter:** core candidate для evidence discipline; обход Figma set и manifest schema — adapter.
- **Ограничение:** это реальный дефект **алгоритма ворот**, найденный локально. Он не доказывает, что весь живой пилот был green; составной случай green-live + UX/DX-unverified вынесен в P-04.

## E-05 — Native Slot существует, но собственная заливка скрывает контент

- **Scenario:** Side Button заменён с иконки на CSV.
- **Representative bad state:** Slot имеет непрозрачный белый fill; вложенный текст CSV тоже белый, хотя его variable binding существует.
- **Почему правдоподобно:** Slot и TEXT реально есть, текст привязан к токену, размеры ненулевые, API-операция завершилась успешно.
- **Observable failure:** CSV неразличим в композиции. S-03 фиксирует ребёнка TEXT внутри Slot, белый fill контейнера и текста; root отдельно сообщил неверное отображение и не засчитал проверку.
- **Pass condition:** CSV различим на фактической поверхности кнопки; Slot не вносит неожиданную подложку; текст находится внутри Slot и переживает штатное изменение длины/размера. Нужен screenshot в контексте и прочтение текста, а не только presence/binding check.
- **Evidence из Haulplane:** R-03, строка 100, «непрозрачный фон Slot»; S-03 с instance 37:36 и Slot I37:36;35:18. R-02 позже сообщает работающий CSV.
- **Core или adapter:** Figma adapter; требование смотреть результат потребителя — core candidate.
- **Ограничение:** **это не P-01**. Дамп как раз показывает ownership вложенного текста. Текущий визуальный результат в этой задаче не переснимался.

## E-06 — Double gap в Button Side

- **Scenario:** Button состоит из label и side-области; агент собирает внешнюю раскладку и fallback как самостоятельные части.
- **Representative bad state:** расстояние уже задано outer layout, а fallback добавляет ещё такой же отступ. Точный исходный набор чисел в repo не сохранён; это реконструкция топологии из записи «двойной gap».
- **Почему правдоподобно:** каждая часть локально выглядит аккуратно, оба расстояния могут ссылаться на допустимые токены.
- **Observable failure:** в собранном Button расстояние складывается дважды; при включении/выключении Side компонент ведёт себя иначе, чем ожидаемый контракт.
- **Pass condition:** измерить один и тот же semantic gap на label+default icon и label+custom side; расстояние задаётся ответственным контейнером один раз. У пустого Side нет случайного остатка. Сравнение проходит с ожидаемым контрактом конкретного Button, без универсального числового значения.
- **Evidence из Haulplane:** R-03, строка 100 — root исправил двойной gap. Отдельный source before screenshot отсутствует.
- **Core или adapter:** Figma adapter.
- **Ограничение:** сначала восстановить минимальный bad fixture; нельзя выдавать его пиксели за фактический исторический export.

## E-07 — Loader смещается при resize

- **Scenario:** loading Button растягивают в контейнере или меняют длину подписи, задающей его ширину.
- **Representative bad state:** loader сохранён в координате первоначального центра; root меняет ширину, а положение loader остаётся прежним.
- **Почему правдоподобно:** в исходной витрине кнопка и spinner идеально центрированы; width/height группы состояний могут совпадать.
- **Observable failure:** после resize spinner визуально не в центре. Источник записывает переделку центрирования; точный offset до неё не сохранён.
- **Pass condition:** на естественной и растянутой ширине центр loader совпадает с центром Button; переключение Loading не вызывает недоговорённого изменения геометрии. Проверить master и consumer instance в контексте, записать размеры и скриншоты.
- **Evidence из Haulplane:** R-03, строка 100; R-02, строки 139–143, root проверил центрирование после изменения ширины. Независимая DX пока открыта.
- **Core или adapter:** Figma adapter. Правило для всех индикаторов вне Button этим случаем не квалифицировано.
- **Ограничение:** описание фиксированной координаты — representative reconstruction; в repo не записана точная причина на уровне API constraints.

## E-08 — Public boundary отвергается по экранному имени/prop

- **Scenario:** reviewer методики решает, может ли product-oriented структура быть публичной частью библиотеки.
- **Representative bad state:** generic инструкция автоматически запрещает public component при наличии экранных свойств, независимо от общего инварианта и реальной операции потребителя.
- **Почему правдоподобно:** такой запрет кажется защитой от domain coupling и слишком больших компонентов.
- **Observable failure:** правило отвергает варианты, которые должны оцениваться по ответственности; root убрал запрет по форме экранных props при приёмке методики.
- **Pass condition:** классификация объясняет владельца common change и local change; экранное имя само по себе не даёт PASS/FAIL. Если evidence применимости отсутствует, результат — предложенная boundary с незакрытой пробой, а не автоматический public export или blanket rejection.
- **Evidence из Haulplane:** R-03, строка 83: «Root убрал запрет по форме экранных свойств»; R-06 — итоговый критерий; R-14 допускает product presentation shape.
- **Core или adapter:** core promotion candidate.
- **Ограничение:** наблюдалась **ошибка правила в harness review**, не неудачная common edit конкретного Haulplane component. Реальное испытание boundary — P-05.

## E-09 — Общая навигация расходится в local copies

- **Scenario:** повторяемую навигацию поддерживают на нескольких экранах изменением независимых локальных фреймов.
- **Representative bad state:** Menu-desktop пересобран локально; состав общего меню отличается между экранами без установленной общей точки изменения.
- **Почему правдоподобно:** каждый отдельный экран выглядит законченным; Navbar остаётся настоящим instance, а высокая общая доля instances маскирует локальную копию навигации.
- **Observable failure:** в аудированном референсе зафиксированы 4 пункта против 7 в разных административных экранах. Это observation reference audit, не Haulplane dispatcher incident.
- **Pass condition:** изменение действительно общего состава навигации достигает всех применений; согласованные различия разных поверхностей сохраняются. Локальное содержимое отдельного экрана меняется независимо. Проверка не требует одного универсального shell и не измеряется процентом instances.
- **Evidence из Haulplane:** R-10, раздел 13; R-11, раздел D, Menu-desktop локален на 20 экранах.
- **Core или adapter:** core candidate о владении изменением; Figma adapter о зависимости instances от masters.
- **Ограничение:** нужен сохранённый reduced fixture или разрешённый повторный просмотр источника перед исполнением; этот пакет не включает сторонний Figma-файл/скриншоты. Намеренные различия меню не следует превращать в дефект автоматически.

## Как использовать corpus сейчас

Каждая карточка пригодна для ручного adversarial review будущего draft. Её нельзя помечать «пройдена» по прочитанному условию. При будущем replay сохранить источник fixture, операцию, фактический результат, сравнение до/после и отдельные технический/DX/UX статусы. Отсутствующее evidence даёт **unknown/not run**, а не PASS.

Подлинные tool snippets уже сохранены для E-01/E-05/E-03; для остальных repo record подтверждает факт, но не заменяет runnable fixture. Создание таких fixtures в Figma в эту read-only задачу не входит.
