# Минимальный extraction-freeze criterion

Статус: **предложение для будущего решения, сейчас freeze не достигнут**. Это критерий извлечения ограниченного среза методики, не новая политика проекта и не разрешение менять Haulplane/Figma.

Freeze наступает, когда есть закреплённая ревизия источника, ограниченный перечень переносимых claims и evidence, позволяющее независимому потребителю повторить заявленные операции. Пока этого нет, LeinoDesign хранит experience; operational source of truth остаётся в Haulplane.

B-01/B-02 допускают одну хорошо выбранную серию операций, которая закрывает несколько проверок. Второе применение нужно как свидетельство независимого локального изменения, а не как универсальная квота числа consumers. Не нужно завершать всю библиотеку или все экраны для freeze узкого среза.

## Дополнительные blockers только для соответствующих обещаний

Эти пункты не следует превращать в обязательный выпуск всего стека, если v0 их не обещает.

| Обещание v0 | Что ещё нужно наблюдать |
|---|---|
| Scoped token maintenance / rollback | Одна принятая область проходит Figma proposal → accepted manifest → SCSS → ONLY sync → проверка; затем change/rollback. Значения вне scope и непринятые предложения сохранены. Сегодня записаны засев и предложения, не полный цикл |
| Vue/Storybook implementation adapter | Один ограниченный компонент доведён по закреплённому snapshot до истории с крайним состоянием и реальным переходом; результат просмотрен в браузере и сопоставлен с Figma. Code build не заменяет визуальную/контрактную приёмку |
| Code Connect | Проверены публикация, mapping и правильность преобразования props на конкретной версии. Наличие API-метода или map entry недостаточно |
| Real dispatcher data acceptance | Пилот получает реальные согласованные примеры и domain observation. Помеченная synthetic fixture позволяет продолжать исследование, но не закрывает этот claim |
| Широкая portability между продуктами/стеками | После Haulplane нужен отдельно ограниченный перенос в другое окружение. Текущая задача его не выполняет; один пилот не подтверждает все design systems |

## Минимальный пакет evidence к решению о freeze

1. Точный source commit и ревизия Figma; один список включённых claims с adapters и project inputs.
2. Короткий журнал независимого consumer: что менял, что должно было сохраниться, что увидел до/после; ссылки на instances и скриншоты в контексте.
3. Результаты negative/positive controls для включённых eval; unknowns не записаны как PASS. Отдельно technical, DX, UX и implementation evidence.
4. Содержательное второе применение и сохранение overrides после common/local edits.
5. Результат применения draft без истории автора, закрытые обнаруженные зависимости и явное решение владельца о смене canonical source в согласованном scope.

Эти материалы сначала появляются в текущем пилоте по его рабочему процессу. Incubation получает адресные evidence updates; он не управляет пилотом параллельным ledger и не замораживает незатронутые решения.

## Что не является критерием

Количество страниц, компонентов, variants, зелёных запусков или прошедших дней; отсутствие ошибок MCP; один красивый screenshot; существующий native SLOT; статусы emoji; процент instances; успешная сборка Storybook; название «универсальный» в документе. Ни одно из них самостоятельно не доказывает заявленный workflow.

Freeze не требует специально причинить потерю overrides в живом продукте. Достаточно проверить сохранность на контролируемой пробе, а искусственные negative fixtures создавать отдельно и честно отмечать их происхождение. Не найденный исторический инцидент остаётся не найденным даже после успешной проверки.
