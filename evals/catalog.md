# Проверки LeinoDesign

Это спецификации повторяемых проб, не отчёт об их прохождении.
Исторический факт, искусственно созданный дефект и новый результат различаются.
Результаты первого применения будут в [trial-2026-09-08](trial-2026-09-08/).
Отсутствующая запись выполнения означает **not run**.

Для выбранного случая сохраняй: входной контракт, происхождение fixture,
операцию, исходный и итоговый IDs/значения, снимок правильного контекста,
ожидание, фактический результат и ограничения. Не требуется выполнять весь
каталог для каждой небольшой правки: выбирай случаи по заявленным возможностям.

Новый автоматический checker проверяй на bad и good, а не только на результате
автора. Проверяй ожидаемую причину отказа; безусловное исключение или ошибка
самого запуска не доказывают, что checker обнаружил дефект. После восстановления
проверь конечный артефакт теми же инвариантами. Bad state создаётся отдельно в пробе или локальной модели checker,
явно отмечается как induced; он не становится историческим инцидентом.
Пример: правильные Large и Small → PASS; убрать reference только у Small →
отказ именно по Small; восстановить → PASS. Проверка на локальных объектах
подтверждает алгоритм, но не поведение Figma.

Неполный replay оставляет отдельные claims открытыми. В частности, успешный
ReviewPanel не подтверждает loader, публикацию, token roundtrip, Vue/Storybook,
работу с реальными данными или весь спектр произвольных дизайн-систем.
