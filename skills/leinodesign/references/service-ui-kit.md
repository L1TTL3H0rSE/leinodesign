# Частные компоненты и UI kit сервиса

Общая библиотека и частные решения продукта имеют разных владельцев. Сначала
проверь оба уровня и существующие композиции. Границу нового компонента выбирай
по [операциям потребителя](components.md), а не только по повторению фреймов.
Устойчивые частные блоки оформляй в UI kit, повторения — связанными экземплярами.
Обычный контейнер раскладки или композиция готовых строк не требуют нового master.

У блока нужны понятные назначение, имя, свойства, необходимые состояния и
поведение по ширине. Независимо изменяемые повторяемые части можно вложить;
не создавай монолит со всеми функциями сервиса и варианты количества записей.

## Найденные компоненты

Проверь известное место UI kit в документации и файле. Если его не удалось
установить, спроси автора о расположении и предложи конкретную организацию.
Если место уже согласовано, продолжай без нового разрешения. Для небольшого
набора может подойти секция рядом с экранами; отдельная страница, файл и
публикация не обязательны. Размер и оформление определяет текущий проект.

Компонент вне UI kit нужно организовать, а не удалять или пересоздавать.
Переноси исходные наборы целиком с сохранением ID, ключей, вариантов и связей.
При переименовании проверь наследование, overrides и прототипные назначения.
Нулевой результат поиска instances не доказывает отсутствие использования.
Изменение общей библиотеки не входит автоматически в работу над сервисом.

До оформления найди авторский образец документации: название, тема, описание,
свойства и демонстрация. При отсутствии нужного референса уточни его, когда он
влияет на результат. Готовую оболочку переиспользуй; при недоступном импорте
обозначь ограничение, не выдавай местную реконструкцию за связанный компонент.
Воспроизведение согласованного оформления не требует пересоздания содержимого.
Не добавляй неподтверждённые версию и статус готовности.

## Каталог и проверка

В существующей памяти продукта сохрани место UI kit, назначение компонентов,
исходные ссылки/ключи, свойства, состояния, вложенные зависимости и страницы
использования. Общие размеры храни один раз в паттерне. Каталог должен быть
доступен из индекса, а новые страницы — ссылаться на использованные решения.

Проверь отдельно внешний вид по референсу, идентичность компонентов и реальные
связи их применений. Запись «UI kit оформлен» в документации не доказывает его
наличия в Figma. При запрете Figma ограничься документами и точным открытым
вопросом. Не превращай один пробел организации в аудит всей библиотеки.
