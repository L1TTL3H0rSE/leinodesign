# Адаптер Figma

LeinoDesign задаёт критерии результата. Точные сигнатуры, доступные методы,
правила шрифтов и ограничения текущего канала бери из его актуальной документации.
Для установленного Figma MCP используй соответствующие навыки работы с API,
создания файла и компонентов. Их шаблоны не расширяют пользовательский scope.

## До записи

- Прочитай целевой узел/страницу, свойства, стили и переменные. Найди
  существующие локальные компоненты и доступные библиотеки.
- Зафиксируй целевые fileKey/IDs и ожидаемое изменение вне Figma, рядом
  с результатами задачи. При продолжении сверяй записи с фактическим состоянием.
- Различай продуктовую композицию, библиотеку и примеры употребления.
  Невозможность импортировать master не меняет владельца продуктового экрана.
  Если путь недоступен, сохрани ограничение; не выдавай локальную копию за
  связанную библиотеку. Если пользователь разрешил локальный черновик, назови его так.

## При сборке

Используй auto-layout для связанных областей. Fill/hug, минимальный размер,
перенос и фиксированная геометрия выводятся из содержимого и контракта.
Абсолютное положение допустимо для наложения, но требует проверки при resize.
Слот не должен получать случайную непрозрачную подложку.

Свяжи значения с выбранными переменными/стилями; у новых переменных задай
уместные scopes. Не выдумывай codeSyntax, если имени в реализации нет:
для предложения обозначь будущий контракт явно. Используй принятый порядок
хранения токенов; SCSS, JSON и конкретная схема коллекций не обязательны.
Literal 0 лучше неверной привязки к ненулевому токену, если нужен именно ноль.

Зарегистрированные TEXT/BOOLEAN/INSTANCE_SWAP должны быть связаны с нужными
слоями каждого включённого варианта. Свойства variant-компонента читай у
родительского COMPONENT_SET; у standalone COMPONENT — у самого компонента.
Документацию Properties выводи из фактических definitions, затем отдельно
проверь их семантику и полноту по входному контракту.

### Уязвимые операции

В исходном пилоте копирование варианта внутри COMPONENT_SET через MCP
теряло references и превращало SLOT в FRAME; standalone-клон их сохранял.
Это наблюдение канала, не вечное ограничение Figma. После clone/combine/swap
проверь типы, связи и фактическую замену содержимого; не доверяй сходству снимка.

При работе со slots отдельно проверь default/custom/empty и сохранность
содержимого. Если обход не возвращает скрытую область, не объявляй её потерянной:
в разрешённой пробе покажи её штатным свойством, проверь содержимое и верни
видимость. После этого сверяй конечное состояние, а не промежуточный снимок.
Возможность конкретного expose/import не выводи только из наличия
метода или ошибки устаревших типов. Недоступную операцию отрази как ограничение.

При ошибке сначала прочитай ответ. Если исход записи неясен, перечитай
целевые узлы перед повтором. Известную ошибку исправляй адресно; повторяющийся
одинаковый отказ канала не обходи серией созданий или платным fallback.

## Проверка

Проверяй ожидаемое значение и владельца связи, а не только наличие ID:
неверный token alias, устаревший RGB paint при верном alias, связь только у
одного размера, пустой manifest и duplicate+missing combination должны
отличаться от корректного результата.

Для clipping, фона и внешних эффектов снимай родителя вместе с instance;
у get_screenshot используй `contentsOnly: false`, когда доступно. Это
не заменяет правильный выбор родителя. Недоступный контекст редактора
не объявляй просмотренным. Перед финальным выводом открой сохранённый снимок.

Доказательство сохранности overrides — фактическое изменение, снимки и значения
до/после, а не `get_metadata` без операции. Публикация/import между файлами,
token roundtrip, Code Connect и работа frontend проверяются отдельно, только
если включены в поручение. Успех локальной пробы их не подтверждает.
